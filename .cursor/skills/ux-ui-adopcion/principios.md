# Principios de baja fricción

Aplicar en este orden. El de arriba gana si dos chocan.

1. **Un trabajo por pantalla.** Si hay que explicar dos objetivos, son dos pantallas.
2. **El siguiente paso es el botón primario.** Lo demás no compite en peso visual.
3. **El primero uso enseña haciendo.** El vacío dice qué falta y ofrece crearlo. No asume seed ni un manual.
4. **Cero capacitación para responder.** El link abre, se responde, se confirma. Sin registro, sin menú, sin dashboard.
5. **Confianza en el número.** Junto al índice: participación (respondieron / esperadas), semáforo y sección más baja. El detalle de la fórmula vive en docs, no en el camino feliz.
6. **El estado se nombra.** Borrador, lista para compartir, esperando respuestas, cerrada. La persona siempre sabe en cuál está y cuál es la única acción útil.
7. **El éxito entrega el objeto del siguiente paso.** Publicar entrega el link. Responder entrega el gracias. Ver resultados entrega qué mirar y el plan de acción.
8. **Error recuperable.** Decir qué falló y la acción concreta (reintentar, volver, corregir el campo). Sin `alert` genérico como diseño.
9. **No perder el lugar.** Lo que se necesita al refrescar va en la URL, no solo en el estado de navegación.
10. **Quitar antes de agregar.** Si un control no avanza el recorrido canónico, se elimina o se esconde del camino feliz.

## Recorrido objetivo del facilitador

Equipo → cuestionario → abrir ronda → copiar link → esperar respuestas → leer termómetro → decidir una acción.

Cada flecha es una pantalla o un momento con una sola primaria. No hace falta ver las seis a la vez.

## Recorrido objetivo del integrante

Abrir link → responder → confirmación. Fin.

## Copy

- Verbo + objeto: "Copiar link para el equipo", "Ver cómo está el equipo", "Crear el primer equipo".
- Evitar: instancia, payload, dashboard como título si se puede decir "Resultados", evaluación cuando se habla de la ronda ya abierta.
- Tuteo consistente (vos). No mezclar con "usted" ni con infinitivos sueltos en botones.
